# Sources and terms

Checked 2026-11-03. Raw downloads live outside the repository (scratch folder). Only scripts,
checksums, aggregate results and small anonymised samples are committed.

## 1. python-dev mailing list archive (email threading)

- Where: https://mail.python.org/pipermail/python-dev/ , plain text files for 2018-November,
  2018-December, 2019-January, 2019-February, 2019-March, 2019-April. Six downloads, 2 to 3 seconds apart,
  one `curl` each, user agent naming this research. SHA-256 of each file: `evidence/raw-sha256-threading.txt`.
- Terms: the site is a public, static archive. `robots.txt` on mail.python.org allows reading with a crawl
  delay of 2 seconds (it disallows only `/*/export/`). I found no written licence or terms page for the
  archive text. I read it only to compute header statistics. I keep no message text, no subjects, no names
  and no addresses in the repository. The committed sample holds salted hashes of ids and senders, and dates.
  The salt is not committed.
- Rejected before use: mail-archives.apache.org (robots.txt disallows bots by default, so I did not
  fetch from it), lore.kernel.org (403 on robots.txt), and Mailman 3 export URLs on python.org (disallowed).
- Pipermail quirk: addresses are rewritten ("name at host"); some In-Reply-To values name ids
  generated by the list software for digest-era mail, and those parents are not in the archive.

## 2. GitHub issues (SLA clocks and QA flag counts)

- Where: GitHub REST API through the authenticated `gh` CLI, GET only: `search/issues` and
  `repos/{repo}/issues/{n}/comments`. Repositories: nodejs/node, pandas-dev/pandas, hashicorp/terraform.
  Roughly 0.3 second pause between calls, a few hundred issues in total, one run.
- Terms: public repository data read through the documented API with a personal token, within rate
  limits, no scraping of HTML. GitHub's terms allow API use for this purpose. Per-person data is not
  published: logins, issue numbers and comment text are not committed. The committed CSV holds only
  repository, window label, and two UTC timestamps per ticket.
- Comment text was held in the scratch folder for the optional QA count and is not committed.
